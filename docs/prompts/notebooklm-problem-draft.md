# NotebookLM で問題の下書きを作るプロンプト

`docs/DESIGN.md` §7.4 の流れで使う。NotebookLM に教材や論点のメモを読み込ませたうえで、下のプロンプトを貼る。
出てきた下書きをもとに、`src/problems/<ラボ>/` に問題テンプレート（TypeScript）を書く。

## 大事な約束

- **数値と正解は NotebookLM に決めさせない。** 下書きに書いてもらうのは「問題文の型」「数値の範囲」「計算の手順（式）」「よくある誤答」まで。正解はアプリの計算エンジン（`src/domain/`）が出す
- **過去問をそのまま写さない。** 過去問を参考にした問題は `src/problems/_private/` に置き、`source.kind: 'past-exam'`・`publishable: false` にする（公開版に含めない）
- 追加したら `npm run validate:problems` を通す（1,000 通りの数値で、解けない問題や紛らわしい誤答がないかを確かめる）

## プロンプト（ここから下をコピー）

```
あなたは中小企業診断士試験（2 次試験・事例Ⅳ、1 次試験・財務会計）の問題作成を手伝います。
読み込んだ資料の論点から、学習アプリに入れる「数値を変えて何度でも解ける問題」の下書きを 3 つ作ってください。

# 論点
（例：CVP 分析の感度分析 ／ 取替投資の NPV ／ 間接法 CF の法人税等の支払額）

# 守ること
- 具体的な数値は書かず、数値はパラメータ（名前・単位・範囲・刻み）で表す
- 正解の数値は書かない。代わりに、パラメータから正解を出す計算式を言葉で書く
- 問題として不自然な組み合わせ（利益がマイナスになる、など）があれば「制約」に書く
- 過去問の文章をそのまま使わない
- 金額の単位は千円（仕訳の問題だけ円）、税率は 30% を基本にする
- 端数処理は事例Ⅳの書き方にそろえる（例：「小数点第 3 位を四捨五入」「千円未満を四捨五入」）

# 出力の形（問題ごとに、この見出しで書く）

## 問題 1：<タイトル>
- 難易度：1〜3
- 論点：<ラボ名：仕訳 / 経営分析 / CF / CVP / 投資>

### パラメータ
| 名前（英字） | 意味 | 単位 | 最小 | 最大 | 刻み |
|---|---|---|---|---|---|

### 制約
- （例：売上高 > 変動費 + 固定費）
- （例：正解とよくある誤答が同じ値にならないよう、変動費率は 50% を除く）

### 問題文
（パラメータは {名前} で埋め込む。表で見せる数値は表として書く）

### 小問
| 番号 | 問い（端数処理を含めて） | 単位 | 配点 | 正解の計算式 |
|---|---|---|---|---|

### よくある誤答
| 小問 | 誤答の計算式 | ヒント（1 文、なぜ間違いか） |
|---|---|---|

### 解説
（計算の手順を 2〜4 文で。数値は {名前} や式で書く）
```

## 下書きからテンプレートへ

1. パラメータの表 → `params`（`{ kind: 'int', min, max, step }`、税率など選択肢は `{ kind: 'choice', values }`）
2. 制約 → `constraint`
3. 正解の計算式 → `src/domain/` の関数を組み合わせる（足りない計算はまず `src/domain/` にテストつきで足す）
4. よくある誤答 → 数値の小問の `commonMistakes`
5. 解説 → `explanation`（`src/problems/helpers.ts` の `text` や表の関数を使う）
6. `src/problems/index.ts` に登録し、`npm run validate:problems` を通す
